# Pyramid Reader

[![Установить](https://img.shields.io/badge/%D1%83%D1%81%D1%82%D0%B0%D0%BD%D0%BE%D0%B2%D0%B8%D1%82%D1%8C-userscript-blue)](https://raw.githubusercontent.com/vasily-fedorov/pyramid-reader/main/pyramid.user.js)
[![Тесты](https://img.shields.io/badge/tests-194-brightgreen)](https://github.com/vasily-fedorov/pyramid-reader)
[![Лицензия](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

Юзерскрипт, который превращает длинную статью в многоуровневую «пирамиду
знаний» в боковой панели: краткая суть → 3–5 главных тем → подтезисы →
атомарные факты, цифры и цитаты.

Работает на любом сайте: текст извлекается через Readability, без правил под
конкретные домены. Модель — любая с OpenAI-совместимым API: DeepSeek по
умолчанию, плюс пресеты OpenAI, OpenRouter и локального Ollama.

Один файл `pyramid.user.js`. Без сборки, без зависимостей, без сервера.

## Зачем

Лонгрид на сорок экранов не хочется читать линейно, чтобы понять, нужен он или
нет. Пирамида даёт три уровня детализации: пробежал суть, раскрыл одну тему,
провалился в факты. Клик по тезису возвращает к тому месту статьи, откуда он
взят.

## Возможности

- **Прогрессивное раскрытие.** Три уровня `<details>`/`<summary>`, в основании —
  списки фактов, цифр и цитат.
- **Стриминг.** Тезисы появляются через пару секунд, а не через минуту.
- **Поле фокуса.** «Только архитектура», «выдели примеры кода на Go» — пирамида
  перестраивается вокруг вопроса.
- **Переход к источнику.** Клик по тезису или факту скроллит страницу к цитате
  и подсвечивает её.
- **Экспорт** в Markdown и Org с сохранением вложенности и языков блоков кода.
- **Язык пирамиды:** язык статьи, русский или английский.
- **Кэш** на 7 дней на статью, фокус и язык: повторный просмотр не тратит
  токены.
- **Свои горячие клавиши:** `Alt+P` / `Alt+M` / `Alt+Q` по умолчанию,
  перенастраиваются записью комбинации.
- **Ширина панели:** перетаскивание за край и `⤢` почти на весь экран.
- **Светлая и тёмная тема** по `prefers-color-scheme`.
- **Изоляция:** closed shadow root — стили сайта не ломают панель, скрипты
  сайта её не читают.
- **Только верхний фрейм.** `@noframes`: скрипт не грузится во встроенных
  iframe, поэтому панель всегда одна на страницу.

## Установка

Нужен менеджер юзерскриптов и ключ к какому-нибудь OpenAI-совместимому API.

### Violentmonkey (рекомендуется)

Открытый исходный код, работает в Chrome, Yandex Browser, Firefox, Edge и Brave.
[Chrome Web Store](https://chromewebstore.google.com/detail/violentmonkey/jinjaccalgkegednnccohejagnlnfdag)
· [Firefox Add-ons](https://addons.mozilla.org/firefox/addon/violentmonkey/)
· [исходники](https://github.com/violentmonkey/violentmonkey).

1. Поставьте расширение, если его ещё нет.
2. Откройте [`pyramid.user.js`](https://raw.githubusercontent.com/vasily-fedorov/pyramid-reader/main/pyramid.user.js)
   — Violentmonkey сам предложит установку. Нажмите «Установить».
3. Откройте любую статью и нажмите `Alt+P`.

### Tampermonkey

То же самое: [tampermonkey.net](https://www.tampermonkey.net/) → «Создать новый
скрипт» → вставить файл → сохранить. Либо открыть ссылку на `pyramid.user.js`
из шапки этого README — Tampermonkey перехватит её так же.

### Обновления

В шапке скрипта прописаны `@updateURL` и `@downloadURL` на `main` этого
репозитория, поэтому менеджер сам предложит обновление после новой версии.
Обновляться вручную из файла не нужно.

### Если ставили вручную раньше

При переходе на версию 1.1 сменились `@namespace` и `@name`, поэтому менеджер
считает скрипт новым. Удалите старый экземпляр («AI Multi-level Artifact
Pyramid Reader») из списка скриптов, иначе рядом будут два и оба будут
перехватывать `Alt+P`.

### Проверка, что скрипт жив

Иконка менеджера на открытой странице показывает скрипт в списке для текущего
сайта — `@match http://*/*` и `https://*/*`, то есть везде. Если списка нет,
скрипт не установился либо страница открыта до установки: перезагрузите её.

## Быстрый старт

1. `Alt+P` — панель откроется и подсветит, что нужен ключ.
2. Ключ API, адрес и модель — в настройках (шестерёнка в шапке панели).
3. Снова `Alt+P` — пирамида построится.

## Настройки

Открываются шестерёнкой в шапке панели или через меню скрипта в расширении
(в Violentmonkey команды лежат в подменю под названием скрипта).

| Поле | По умолчанию | Что это |
|---|---|---|
| Адрес API | `https://api.deepseek.com` | база OpenAI-совместимого API |
| Ключ API | — | Bearer-токен, хранится только в хранилище менеджера |
| Модель | `deepseek-flash` | имя модели, поле редактируемое |
| Макс. символов | `60000` | сколько текста статьи отправлять |
| Макс. токенов | `8192` | лимит ответа |
| Температура | `0.3` | детерминированность |
| Таймаут, с | `180` | предел ожидания ответа |
| Использовать Readability | включено | выключить — брать `article`/`main`/`body` напрямую |
| Режим размышлений | выключено | reasoning-режим DeepSeek, медленнее и дороже |
| Язык пирамиды | на языке статьи | либо на русском, либо на английском |
| Горячие клавиши | `Alt+P` / `Alt+M` / `Alt+Q` | перенастраиваются записью |

### Пресеты

| Пресет | Адрес | Модель |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| Ollama | `http://localhost:11434/v1` | `llama3.1` |

Для Ollama запустите сервер с `OLLAMA_ORIGINS=*`, иначе браузер заблокирует
запрос. Если аккаунт не знает имя модели из пресета, впишите своё: поле
редактируемое.

## Горячие клавиши

| Действие | По умолчанию |
|---|---|
| Открыть панель / скрыть | `Alt+P` |
| Развернуть / свернуть | `Alt+M` |
| Перейти к полю вопроса | `Alt+Q` |
| Закрыть панель | `Esc` |

На macOS по умолчанию `Ctrl+Alt+P/M/Q`: там `Option` печатает символы вместо
букв.

Все три комбинации меняются в настройках: нажмите кнопку с текущей
комбинацией, затем введите новую. `Esc` во время записи отменяет её.
Комбинация без `Ctrl`/`Alt`/`Meta` не принимается (кроме одиночных `F1…F24`),
иначе обычная буква перехватывала бы ввод на всех сайтах. Занятые браузером
(`Ctrl+P`, `Ctrl+S`, `F5` и подобные) помечаются предупреждением, но
сохраняются.

Хоткеи работают и когда курсор внутри панели, и когда панель закрыта. В чужих
полях ввода на странице они не перехватываются.

## Как пользоваться

**Поле фокуса.** Введите предмет интереса — «только архитектура», «выдели
примеры кода на Go» — и нажмите `↻` или `Enter`. Пирамида перестроится строго
вокруг этого. Пустое поле — обычная пирамида по всей статье. Если в статье нет
материала по теме, модель скажет об этом в Executive Summary и не станет
выдумывать.

**Состояния.** Пока модель думает, в шапке «модель думает…» с таймером — это
нормальное состояние reasoning-моделей, а не зависание. «Отменить» прерывает
запрос и оставляет уже полученную часть.

**Что ушло в модель.** Ссылка «показать отправленный текст» внизу панели
показывает ровно тот текст, который был отправлен. Первое, что стоит открыть,
если пирамида получилась странной: виноват экстрактор или модель.

**Переход к источнику.** Клик по тезису или факту прокручивает страницу к тому
месту статьи, откуда он взят, и подсвечивает его рамкой на полторы секунды.
Модель присылает для этого дословную цитату; у пирамид, построенных до
появления этой возможности, берётся текст самого тезиса. Если совпадения нет,
в панели на пару секунд появляется «Не нашёл это место в статье.».

**Ширина.** Потяните за левый край панели или нажмите `⤢` в шапке. Ширина
запоминается между сессиями.

## Экспорт

Кнопки «↓ MD» и «↓ Org» в подвале панели скачивают пирамиду файлом.

Заголовки сохраняют вложенность панели: `<h3>` → `##` (`**` в Org), каждый
`<details>` — на уровень глубже. Факты идут маркированным списком, код —
огороженным блоком с языком (`#+begin_src js` в Org), цитаты — `>` /
`#+begin_quote`, таблицы — pipe-строками. Первая строка файла — заголовок
страницы.

Имя файла транслитерируется из заголовка и получает дату:
`kak-rabotaet-event-loop-2026-10-31.md`. Кнопки неактивны, пока пирамида не
отрисована.

## Язык пирамиды

Три варианта в настройках: язык статьи (по умолчанию), русский, английский.
Язык входит в ключ кэша, поэтому переключение сразу строит пирамиду заново, а
не отдаёт старую на другом языке.

Заголовки структуры (`📌 Executive Summary`, `📐 Тезисы`) не переводятся: это
контракт разметки, по нему работают очистка ответа, экспорт и тесты.

## Кэш

Ответ кэшируется на 7 дней отдельно для каждой комбинации «статья + фокус +
язык», до 10 записей, до 96 КБ на запись. Повторное открытие той же статьи не
тратит токены. «Перестроить пирамиду» (`↻`) кэш игнорирует — это осознанный
запрос заново.

Очистка: меню скрипта → «Очистить кэш».

## Как это работает

1. **Извлечение.** Клон документа, из него вырезаются `nav`, `aside`, `footer`,
   `form`, баннеры и прочая обвязка. Readability выделяет тело статьи. Если не
   справился — берётся `article` / `main` / `[role=main]` / `body` уже на
   очищенном клоне, а в панели появляется пометка. Блоки кода переносятся
   дословно, с отступами и языком.
2. **Запрос.** `POST {apiBase}/chat/completions` со стримингом, два сообщения:
   системный промпт со структурой пирамиды и текст статьи. Сеть — только через
   `GM_xmlhttpRequest`, поэтому CORS сторонних сайтов не мешает.
3. **Ответ.** SSE разбирается по мере прихода: кадры перерисовываются раз в
   200 мс, финальная отрисовка синхронная. Markdown-обёртка снимается, если
   модель её добавила.
4. **Очистка.** Ответ модели — недоверенный HTML. Разрешён белый список тегов,
   все атрибуты удаляются; единственное исключение — `data-src` с цитатой для
   перехода к источнику. `script`, `style`, `iframe`, `img`, `svg`, `form`
   удаляются вместе с содержимым.
5. **Рендер.** Панель живёт в closed shadow root: стили сайта внутрь не
   проникают, разметка панели недоступна скриптам страницы.

## Приватность и безопасность

- **Ключ не покидает браузер.** Он хранится в хранилище менеджера скриптов
  (`GM_setValue`) и уходит только в выбранный вами API. Никакого прокси,
  бэкенда или телеметрии.
- **Ключ не попадает в DOM.** Сохранённый ключ не подставляется в поле
  настроек: пустое поле при сохранении оставляет прежний, рядом есть «Очистить
  ключ». Панель в closed shadow root, поэтому скрипты сайта не могут её
  прочитать.
- **Текст статьи уходит в API**, который вы выбрали. Это очевидно, но стоит
  помнить: для облачных моделей статья покидает ваш компьютер. С Ollama — не
  покидает.
- **Синтетические нажатия не тратят токены.** Хоткей срабатывает только на
  доверенные события: скрипт сайта не может программно вызвать запрос.
- **Ответ модели не исполняется.** Санитайзер по белому списку, все атрибуты
  вырезаются.

## Ограничения

- Пейволы, логин-воллы и «показать полностью» не обходятся: используется то,
  что уже есть в DOM.
- SPA-страницы читаются в состоянии на момент нажатия.
- Длинные статьи обрезаются до «Макс. символов» (по умолчанию 60 000); в
  панели видно, сколько отправлено и сколько было.
- Токены в подвале показываются только если сервер прислал `usage` (DeepSeek
  присылает, часть других — нет).
- Для `deepseek-flash` режим размышлений выключен принудительно: иначе
  размышления съедают общий бюджет `max_tokens` и ответ приходит пустым.
  Включается галочкой в настройках.

## Разработка

Нужен Node ≥ 18.

```bash
npm install
npm test        # 194 теста на node:test + jsdom
```

Стенд без трат токенов:

```bash
node test/mock-server.mjs
```

Откройте `http://127.0.0.1:8787/` — страница сама подставляет
`apiBase: http://127.0.0.1:8787/v1` в `localStorage`. Флаги в адресе:

| Флаг | Что делает |
|---|---|
| `?fail=401` / `?fail=429` / `?fail=500` | ответ с ошибкой |
| `?plain=1` | целый JSON вместо SSE |
| `?slow=1` | чанки с задержкой 150 мс |
| `?xss=1` | в ответе `<script>` и `<img onerror>` |
| `?think=0` | отключить reasoning-чанки |
| `?usage=0` | не присылать `usage` |

В конце каждой пирамиды стенд добавляет блок `debug: system prompt`, чтобы
видеть, какой промпт реально ушёл.

### Структура

```
pyramid.user.js                  единственный устанавливаемый файл
vendor/Readability.js            @mozilla/readability 0.5.0, Apache-2.0
scripts/sync-readability.mjs     переинлайнивает vendor в pyramid.user.js
test/*.test.mjs                  тесты на node:test
test/helpers/load-userscript.mjs запускает скрипт в jsdom с шимом GM_*
test/fixtures/                   страницы по типам вёрстки
test/mock-server.mjs             стенд: SSE и флаги ошибок
docs/superpowers/                дизайн-документ и план реализации
```

`pyramid.user.js` держит все секции по порядку, разделённые заголовками:
конфиг → хранилище → кэш → санитайзер → промпт → экспорт → Readability →
экстрактор → SSE → клиент API → панель → настройки → триггеры. Файл один
намеренно: это артефакт, который пользователь копирует в менеджер скриптов.

`vendor/Readability.js` инлайнится между маркерами. После обновления
библиотеки:

```bash
node scripts/sync-readability.mjs
```

Отдельный тест сверяет инлайн с вендорным файлом побайтово, чтобы они не
разъехались.

### Как устроены тесты

Скрипт запускается целиком в jsdom: `test/helpers/load-userscript.mjs`
подставляет `GM_*` и читает настоящий `pyramid.user.js`. В конце файла есть
хук `window.__pyramid`, который включается только при
`globalThis.__PYRAMID_TEST_HOOK__` — продакшн-путь инициализации он не
затрагивает.
