## 1. Что делаем и зачем

Юзерскрипт для Tampermonkey / Violentmonkey, который по `Ctrl+Shift+P`
(`Cmd+Shift+P` на Mac) берёт текст открытой статьи, отправляет его в
OpenAI-совместимый API и показывает в правой боковой панели
многоуровневую «пирамиду знаний»: executive summary → 3–5 главных тем →
2–3 подтезиса на каждую → атомарные факты, цифры и цитаты в основании.

Зачем: длинный текст на **любом** сайте удобнее просматривать сверху вниз по
тезисам, раскрывая только нужную ветку, чем читать линейно. Цель — чтение по
всему браузеру, а не поддержка одного сайта.

## 2. Границы

**Делаем**
- Один устанавливаемый файл `pyramid.user.js`, без сборки и зависимостей на этапе установки.
- Локальный стенд `test/` (§9) для проверки без трат токенов.
- Извлечение основного текста на произвольных сайтах, одним путём, без
  списка особых случаев (§6.1).
- Стриминг ответа: пирамида появляется по мере генерации.
- Пирамида на языке статьи.
- Поле фокуса: ввод «только архитектура» / «выдели примеры кода на Go»
  перестраивает пирамиду под предмет интереса (§6.3, §6.7).
- Боковая панель с прогрессивным раскрытием, светлая/тёмная тема.
- Настройки (эндпоинт, ключ, модель) в отдельном окне, сохранение в `GM_setValue`.
- Кэш ответа по статье, чтобы повторный вызов не тратил токены.
- Понятные ошибки с действием (открыть настройки / закрыть).

**Не делаем (non-goals)**
- Упаковку в MV3-расширение, публикацию в Chrome Web Store и т.п.
- Перевод, озвучку, экспорт в Markdown/PDF, подсветку прямо в тексте статьи.
- Собственный backend, прокси, хранение ключей на сервере.
- Работу на страницах без осмысленного текста (главные, каталоги, SPA-дашборды).
- Обход пейволов, логин-волл, «показать полностью» и бесконечной подгрузки —
  работаем с тем, что уже есть в DOM.

**Anti-goals** — считается провалом, даже если технически работает
- Ответ модели ломает вёрстку сайта или исполняет скрипт на странице.
- Ключ API утекает в DOM страницы, в лог или в сеть третьей стороне.
- Панель перекрывает контент так, что закрыть её нельзя с клавиатуры.
- После ошибки API пользователь видит `[object Object]` или пустой экран.

## 3. Ограничения

- Менеджер юзерскриптов даёт `GM_xmlhttpRequest`, `GM_setValue`, `GM_getValue`,
  `GM_registerMenuCommand`. `fetch` к стороннему API упирается в CORS, поэтому
  сеть — только через `GM_xmlhttpRequest` (как и требует ТЗ).
- Хранилище `GM_*` общее для всех сайтов и имеет пределы объёма — кэш ограничиваем.
- Сайты диктуют вёрстку: глобальные правила для `details`, `summary`,
  `font-size` и `*` встречаются часто и ломают внешний вид. Нужна изоляция.
- Модель отвечает HTML, который мы не контролируем. Это недоверенный ввод.

## 4. Варианты и выбор

- **A. Строго по ТЗ, минимум.** Константы в шапке файла, запрос без стриминга,
  `body.innerText` как fallback. Просто, но пустой экран 10–60 с и мусор
  (меню, футер) в запросе на большинстве сайтов.
- **B. Один файл + Readability + стриминг.** Выбран.
- **C. Модули + esbuild.** Лишний шаг сборки ради одного файла.

Выбран **B**: качество извлечения текста — то, на чём «оптимизировано под
технические лонгриды» ломается в первую очередь, а стриминг убирает главную
боль ожидания. Итог всё равно один `.user.js`.

## 5. Поток

```
Ctrl+Shift+P
  → панель: состояние "извлечение"
  → извлечь текст (Readability → fallback), обрезать до maxChars
  → кэш по ключу (статья + фокус)?
      да  → отрендерить, бейдж "из кэша"
      нет → GM_xmlhttpRequest, stream: true
             → onprogress: накопить дельты, перерисовать (троттлинг 200 мс)
             → done: включить интерактивность, записать в кэш
             → error: карточка ошибки с текстом и кнопками
  → ввод фокуса + "Перестроить пирамиду"
      → abort текущего, новый запрос с тем же текстом и новым фокусом
      → дерево тезисов заменяется целиком
  → повторный хоткей / Esc / X → закрыть; незавершённый запрос → abort
```

## 6. Решения по частям

### 6.1 Извлечение текста

Один путь для всех сайтов, без списка особых случаев:

1. Клон документа, из клона удаляются
   `script, style, noscript, nav, aside, footer, form, iframe, svg, canvas,
   [aria-hidden="true"], .cookie, .newsletter, .subscribe`.
2. Readability (`@mozilla/readability`, UMD-сборка инлайнится в файл)
   на клоне.
3. Если Readability упал или дал < 500 символов: `article`, `main`,
   `[role="main"]`, `[itemprop="articleBody"]`, иначе `body` — **на том же
   клоне** с уже удалёнными `nav/aside/footer/form`, иначе fallback вернёт в
   запрос ровно ту обвязку, которую убрал шаг 1.
4. Нормализация по блокам: абзацы и заголовки разделяются пустой строкой,
   внутри абзаца пробелы схлопываются, не более двух переводов строки подряд.
5. Блоки `<pre>` и `<code>` не схлопываются: внутренние отступы и переводы
   строк сохраняются дословно, блок оборачивается в ```` ``` ````-ограждение
   с языком из `class="language-*"`, если он есть.
6. Обрезка до `maxChars` (60 000) по границе абзаца; в панели пометка
   «текст обрезан, отправлено N из M символов».

Readability инлайнится из `@mozilla/readability` (Apache-2.0, заголовок лицензии
сохраняется). Если на этапе реализации библиотеку получить не удастся —
пишется компактный собственный экстрактор по плотности абзацев (~80 строк),
интерфейс тот же. Это решает исполнитель, на продукт не влияет.

**Почему без спецслучая Хабра.** Сайтов, которые надо поддержать, — все;
перечислять селекторы под каждый нельзя, а Readability на типовой статье
справляется не хуже ручного селектора. Один путь проще проверять и он не
ломается, когда сайт меняет вёрстку.

**Код в статьях.** Документация и технические посты живут кодом, поэтому
пункт 5: без него отступы Python и куски YAML приезжают в модель сплющенными
в строку, и факты в основании пирамиды становятся мусором.

**Readability не выделил статью.** Если `autoExtract` включён, но Readability
не дал результата, в панели появляется пометка «Readability не выделил статью —
отправлен текст страницы». Без неё пользователь не понимает, почему пирамида
описывает меню вместо статьи.

**Страница без статьи.** ТЗ прямо говорит: для остальных сайтов брать
`document.body.innerText`, поэтому отказа не делаем — отправляем что нашли.
Но если текста меньше 400 символов, в шапке панели показывается предупреждение
«похоже, это не статья — текст короткий», чтобы пользователь не искал ошибку
в модели. Это наш вызов, не требование ТЗ.

**Ссылки.** В отправляемом тексте URL не вырезаются: в технических статьях
ссылка часто несёт смысл («см. RFC 9110»). Это осознанно.

**Что именно ушло в модель.** В подвале панели — сворачиваемый блок
«показать отправленный текст» с тем же текстом, что ушёл в запрос. На разных
сайтах извлечение ведёт себя по-разному, и без этого невозможно понять,
виноват экстрактор или модель. Стоит ~10 строк, экономит часы догадок.

### 6.2 Санитайзер (обязательно)

Ответ модели — недоверенный HTML. Порядок:
1. `DOMParser.parseFromString(html, 'text/html')` в отдельном документе.
2. Обход дерева: оставляем только разрешённые теги, **все атрибуты
   удаляются** (`onerror`, `style`, `href`, `src` — всё). Единственное
   исключение — `data-src` на `details`/`summary`/`li` (§6.1): он нужен для
   перехода к месту в статье и содержит только текст, обрезанный до 400
   символов.
   Белый список: `h3 h4 h5 p ul ol li details summary strong b em i code pre
   blockquote br hr span div table thead tbody tr th td`.
   `script, style, iframe, object, embed, img, svg, link, meta, form, input`
   — удаляются вместе с содержимым. Неизвестные теги разворачиваются в текст.
3. Комментарии удаляются.
4. Чистый узел вставляется в панель.

**Отклонение от ТЗ:** промпт просит `<details style="margin-left: 20px;">`.
Инлайн-стили мы вырезаем, поэтому вложенность оформляется CSS
(`details details { margin-left: 18px; border-left: … }`), а модели
дополнительно говорится «не используй inline-стили и атрибуты».
Визуальный результат тот же, поверхность атаки меньше.

### 6.3 API

- По умолчанию DeepSeek: `apiBase = https://api.deepseek.com`,
  `model = deepseek-flash`. Остальные провайдеры — пресетами в настройках.
- `POST {apiBase}/chat/completions`, заголовки `Authorization: Bearer …`
  (только при непустом ключе), `Content-Type: application/json`.
- Тело: `model`, `temperature` (0.3), `max_tokens` (8192), `stream: true`,
  два сообщения — system и user (`Статья:\n\n<текст>`).
- Для хостов `deepseek.com` добавляется `thinking: {type: 'disabled'}` —
  иначе DeepSeek включает режим размышлений по умолчанию, `reasoning_content`
  съедает общий бюджет `max_tokens`, и `content` приходит пустым с
  `finish_reason: "length"`. Другим провайдерам это поле не отправляется:
  неизвестный параметр может дать 400. Включается обратно в настройках
  («Режим размышлений»).

**Почему DeepSeek дефолтом.** Это OpenAI-совместимый эндпоинт, который уже
отдаёт финальный чанк с `usage` — счётчик токенов в подвале работает без
дополнительных полей запроса. Ключ пользователя при этом живёт в
`GM_setValue`, а не в коде.

**Почему размышления выключены по умолчанию.** У `deepseek-flash` параметр
`thinking.type` по умолчанию `enabled`, а `max_tokens` — общий бюджет на
`reasoning_content` и `content` вместе. На длинной статье размышления
съедают весь бюджет, `content` остаётся пустым, `finish_reason` приходит
`length`. Пирамида не требует цепочки рассуждений, поэтому режим выключен и
включается галочкой, когда нужен.

**Диагностика пустого ответа.** `finish_reason` запоминается, и пустой
`content` объясняется по нему: `length` — лимит токенов или размышления,
`content_filter` — фильтр, `insufficient_system_resource` — ресурсы,
`aborted` — прерывание сервером, иначе — «пустой ответ». Без этого
пользователь видел одно и то же сообщение на пять разных причин.

**Reasoning-модели.** DeepSeek в режиме размышлений стримит
`delta.reasoning_content` отдельно от `delta.content`. Мы читаем только
`content`, поэтому размышления в пирамиду не попадают. Побочный эффект:
пока модель думает, `content` пуст — панель обязана показывать состояние
«модель думает…» с таймером, а не пустой экран (§6.7).

**Токены.** Если финальный чанк содержит `usage.completion_tokens` — пишем
его в подвал. Нет `usage` (часть OpenAI-совместимых серверов) — подвал
показывает только символы. Никаких оценок «на глаз».

**System-сообщение — дословно (база из ТЗ):**

```
Проанализируй текст статьи и сформируй ГЛУБОКУЮ МНОГОУРОВНЕВУЮ Пирамиду Знаний
на языке статьи (русский текст — по-русски, английский — по-английски, и так
далее). Используй вложенные HTML-теги <details> и <summary> для
прогрессивного раскрытия информации. Отвечай ТОЛЬКО чистым HTML-кодом без
markdown-оберток (без ```html).

Структура ответа:
- <h3>📌 Executive Summary</h3> + 2-3 предложения сути статьи.
- <h3>📐 Тезисы</h3>
- Уровень 2: 3-5 главных тем статьи в тегах <details>. Внутри <summary> пиши
  четкий тезис.
- Уровень 3 (Вложенный): Внутри каждого тега Уровня 2 должно быть 2-3 подтезиса
  (тоже в тегах <details>).
- Уровень 4 (Основание пирамиды): Внутри подтезисов Уровня 3 должны лежать
  атомарные факты, цифры, примеры кода или цитаты в виде списков <ul>/<li>.
```

**Дополнение к system-сообщению (наше, не из ТЗ):**

```
Не используй атрибуты style, class, id, href, src и любые inline-стили.
Вложенность второго уровня оформляй обычной вложенностью <details>, без
margin-left. Не выводи ничего, кроме HTML.
```

**Дополнение при непустом поле фокуса** — добавляется третьим блоком только
когда в поле что-то введено:

```
Сформируй пирамиду строго относительно следующего предмета интереса
пользователя: <текст из поля ввода>

Если в статье нет материала по этому предмету, так и напиши в Executive
Summary и не выдумывай факты. Язык ответа — язык статьи.
```

Фокус — это линза, а не новая тема: пункт про отсутствие материала стоит
там специально, иначе модель на «выдели примеры кода на Go» в статье без Go
начинает досочинять примеры.

**Заголовок раздела — «Тезисы».** Старое название «Многоуровневые Тезисы» при
рендере нормализуется до «Тезисы»: так уже закэшированные пирамиды и ответы
моделей, скопировавших прежний промпт, выглядят одинаково.

**Язык пирамиды = язык статьи.** На английской документации русский пересказ
не с чем сверить: термины, имена API и куски кода в нём искажаются. Пометка
в Executive Summary остаётся на языке статьи по той же причине.
- Стриминг: `GM_xmlhttpRequest` с `onprogress`; читаем только новый хвост
  `responseText`, строки `data: …`, `[DONE]` завершает поток,
  `choices[0].delta.content` накапливается.
- Если сервер проигнорировал `stream` и вернул целый JSON — определяем по
  отсутствию `data:` и берём `choices[0].message.content`.
- Перед рендером снимается markdown-обёртка: начальная строка ```` ```lang ````
  и закрывающие ```` ``` ````, если модель их всё-таки добавила. Применяется и
  к промежуточным кадрам стриминга, и к финальному рендеру, и к ответу из кэша.
- Отмена: `GM_xmlhttpRequest` возвращает хэндл с `.abort()`. `AbortController`
  из ТЗ неприменим — это его эквивалент в GM API.
- Таймаут 180 с.

### 6.4 Ошибки

Разбор ответа: `error.message` / `message` / текст. Маппинг:
- 401/403 → «Неверный ключ API», кнопки «Настройки» / «Закрыть».
- 402/429 / `insufficient_quota`, `rate_limit` → «Закончились токены или
  превышен лимит запросов».
- 404 → «Модель или адрес не найдены» + подстановка текущих значений.
- 400 → текст от сервера как есть (обычно про модель или контекст).
- Сеть/таймаут/CORS → «Не удалось связаться с API. Проверьте адрес и доступ
  к нему из браузера».
- Пустой ответ → «Модель вернула пустой ответ».
Никогда не показываем сырой JSON целиком, только извлечённое сообщение.

### 6.5 Кэш

- Ключ: `pyr.cache.` + `djb2(url + '|' + text.length + '|' + text.slice(0,64)
  + '|' + focus)`.
- Значение: `{ ts, html, focus }`. TTL 7 дней, хранится максимум 10 записей
  (старые вытесняются), HTML в записи обрезается до 96 КБ.
- `focus` в ключе обязателен: иначе кэш от «только архитектура» отдастся при
  пустом поле, и наоборот. Каждый фокус — отдельная запись.
- «Перестроить пирамиду» всегда идёт в API, минуя кэш: это осознанное
  действие пользователя, а не повторный просмотр. Кэш при этом перезаписывается
  для текущего фокуса. Кнопка и `Enter` вызывают `runPyramid({force:true})`.
- Пункт меню «Очистить кэш».

Перечисление и удаление записей требует `GM_listValues` / `GM_deleteValue`.
Оба менеджера их поддерживают, поэтому в шапку добавляются
`@grant GM_listValues` и `@grant GM_deleteValue` сверх набора из ТЗ.
Отдельный ключ-индекс не заводим — он даёт лишнее состояние для рассинхрона.

### 6.6 Настройки

Одно окно, открывается пунктом меню и шестерёнкой в шапке панели.
Хранение — один ключ `pyr.config` (JSON в `GM_setValue`).

| Поле | Дефолт | Смысл |
|---|---|---|
| `apiBase` | `https://api.deepseek.com` | база OpenAI-совместимого API |
| `apiKey` | `''` | Bearer-токен |
| `model` | `deepseek-flash` | имя модели |
| `maxChars` | `60000` | лимит отправляемого текста |
| `maxTokens` | `8192` | лимит ответа |
| `temperature` | `0.3` | детерминированность |
| `timeoutSec` | `180` | таймаут запроса |
| `autoExtract` | `true` | включать Readability |
| `thinking` | `false` | режим размышлений DeepSeek |
| `hotkeys` | `Alt+P` / `Alt+M` / `Alt+Q` | `{toggle, wide, focus}`, см. §6.10 |

Конфиг, сохранённый до появления поля `thinking`, мигрируется один раз:
`maxTokens` поднимается с прежнего дефолта 4096 до 8192, `thinking`
выставляется в `false`. Явно выбранный после миграции `maxTokens`
сохраняется.

Пресеты-кнопки (заполняют `apiBase`/`model`):

| Пресет | `apiBase` | `model` |
|---|---|---|
| DeepSeek (по умолчанию) | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| Ollama | `http://localhost:11434/v1` | `llama3.1` |

Поле `model` остаётся редактируемым: если аккаунт не знает `deepseek-flash`,
пользователь правит одно поле, а не лезет в код. Ollama требует
`OLLAMA_ORIGINS=*` на стороне сервера — пишем это подсказкой в окне.
Ключ вводится в `type="password"` с кнопкой «показать». Сохранённый ключ в
поле не подставляется: при открытии окна поле пустое, а подсказка говорит,
сохранён ли ключ. Сохранение с пустым полем оставляет прежний ключ; отдельная
кнопка «Очистить ключ» его удаляет. Так ключ не появляется в DOM даже на время
открытого окна.

### 6.7 UI

- Хост: `div#ai-pyramid-host` с `all: initial`, `position: fixed`,
  `z-index: 2147483646`, внутри — **closed shadow root**. Изоляция от CSS сайта
  и от скриптов страницы: при `open` любой скрипт на сайте может прочитать
  `host.shadowRoot` и, например, поле ключа. `closed` даёт ту же изоляцию
  стилей и закрывает доступ к разметке панели.
- Панель: `right: 0; top: 0; height: 100vh`, ширина по умолчанию 420 px,
  выезд `translateX(100%) → 0` за 220 мс.
- Ширина: перетаскивание за левый край (полоса 6 px, `role="separator"`,
  стрелки ←/→ с шагом 40 px) в диапазоне 340 px … 98 % окна; кнопка `⤢`
  разворачивает почти на весь экран (96 vw) и обратно. Ширина и состояние
  разворота хранятся в `pyr.ui` и переживают перезагрузку.
- Шапка: заголовок, бейдж состояния, кнопки «Настройки», «Закрыть (X)».
  Отдельной кнопки «Перегенерировать» в шапке нет: её роль играет
  «Перестроить пирамиду» в полосе фокуса, чтобы не было двух кнопок с
  одинаковым смыслом.
- **Полоса фокуса** — под шапкой, над Executive Summary, `position: sticky`
  внутри панели, чтобы не уезжала при скролле:
  - `input[type="text"]` с подсказкой «фокус, например: только архитектура»;
  - кнопка-иконка `↻` с `aria-label`/`title` «Перестроить пирамиду» (текст в
    полосе не помещается и конкурирует с полем ввода);
  - `Enter` в поле = нажатие кнопки; пустое поле = дефолтный промпт;
  - во время `requesting`/`streaming` поле и кнопка `disabled`, в кнопке
    «Отменить»;
  - значение поля переживает перерисовку панели и повторное открытие в рамках
    вкладки; в `GM_setValue` не пишется — это разовый инструмент, а не
    настройка.
- Тело: скролл, отрендеренная пирамида.
- Подвал: «отправлено N из M символов», «ответ: K символов», токены (если
  сервер их прислал), модель; справа — кнопки «↓ MD» и «↓ Org».
  Токены — только если сервер прислал `usage.completion_tokens` в финальном
  чанке (DeepSeek присылает); иначе строки про токены просто нет.
- Перерисовка во время стриминга сохраняет `scrollTop` и набор открытых
  `<details>`: иначе раскрытая ветка схлопывается каждые 200 мс.
- Состояния: `extracting`, `requesting` (таймер секунд + «Отменить»),
  `streaming` (частичный HTML, read-only, бейдж «генерация…»),
  `thinking` (запрос ушёл, `content` ещё пуст — бейдж «модель думает…» с
  таймером; это нормальное состояние reasoning-моделей, а не зависание),
  `done`, `error`, `cached`.
- Тема: CSS-переменные + `@media (prefers-color-scheme: dark)`.
  Системный sans-serif, отступы 16 px, `summary { cursor: pointer }`,
  кастомный маркер `▸ → ▾`, `details[open] > summary`.
- Доступность: `role="dialog"`, `aria-label`, фокус в панель при открытии,
  `Esc` закрывает, X и Cancel — настоящие `<button>`.

### 6.8 Переход к месту в статье

Клик по `<summary>` или `<li>` в панели уводит страницу к тому месту статьи,
откуда взят тезис или факт.

1. Берётся `data-src`; если его нет (старая закэшированная пирамида) — текст
   самого узла.
2. Цитата и текст страницы токенизируются по `[\p{L}\p{N}]+` и сравниваются
   без учёта регистра, пунктуации и лишних пробелов.
3. Ищется первое совпадение подряд идущих токенов. Если целиком не нашлось —
   пробуются префиксы короче (до 3 токенов): модель иногда дописывает лишнее
   слово в конце цитаты.
4. Найденный элемент прокручивается в центр (`block: 'center'`) и на 1.6 с
   подсвечивается рамкой. Подсветка — собственный элемент поверх страницы;
   DOM статьи не меняется.
5. Если не нашлось ничего — в строке пометок панели на 2.6 с появляется
   «Не нашёл это место в статье.», затем возвращается прежняя пометка.

Поиск идёт по `document.body`, но пропускает `script/style/nav/aside/footer/
form`, элементы управления, классы `.cookie/.newsletter/.subscribe` и саму
панель: иначе цитата цепляется за меню. Клик по `<summary>` одновременно
раскрывает ветку — это его штатное поведение.

### 6.9 Экспорт

Пирамида экспортируется в Markdown и Org. Источник — уже отрендеренный и
очищенный HTML панели, поэтому в файл не попадает ничего, что не прошло
санитайзер.

- `<h3>` → `##` (org: `**`), `<details>` → заголовок на уровень глубже
  (org: `***`), вложенные `<details>` — дальше по глубине.
- `<ul>/<ol>` → `-` / `1.` с отступом 2 пробела на уровень вложенности.
- `<pre><code class="language-x">` → ```` ```x ```` (org: `#+begin_src x`).
- `<blockquote>` → `>` (org: `#+begin_quote`), `<hr>` → `---` (org: `-----`),
  таблицы → pipe-строки.
- Первая строка файла — `# <title>` (org: `* <title>`).
- Имя файла: транслитерированный `document.title`, обрезанный до 60 символов,
  плюс дата, `.md` / `.org`. Пустой заголовок → `pyramid`.
- Кнопки неактивны, пока в панели нет содержимого.

### 6.10 Триггеры

- Три настраиваемых хоткея, по умолчанию `Alt+P` / `Alt+M` / `Alt+Q`
  (на macOS `Ctrl+Alt+P/M/Q`, потому что Option даёт символы):

  | Действие | По умолчанию | Что делает |
  |---|---|---|
  | `toggle` | `Alt+P` | открыть панель (и построить, если пусто) или скрыть |
  | `wide` | `Alt+M` | развернуть/свернуть; при закрытой панели сначала открывает |
  | `focus` | `Alt+Q` | открыть и поставить курсор в поле вопроса |

- Комбинация сравнивается как каноническая строка: модификаторы в порядке
  `Ctrl+Alt+Shift+Meta`, буква в верхнем регистре (`Alt+p` → `Alt+P`).
- Комбинация без `Ctrl`/`Alt`/`Meta` не принимается, кроме одиночных `F1…F24`:
  иначе обычная буква перехватила бы ввод.
- `Ctrl+Shift+P` не используется: в браузерах он занят (печать, приватное окно),
  а при фокусе в поле мы его не перехватывали — браузер открывал своё меню.
- Комбинации, занятые браузером (`Ctrl+P/S/F/T/W/N`, `Ctrl+Shift+P/I/J/C`,
  `F5`, `F11`, `F12`), помечаются предупреждением, но сохраняются: возможно,
  пользователь сознательно хочет перекрыть браузер.
- Хоткей срабатывает и когда фокус внутри нашей панели (в том числе в поле
  вопроса) — там он нужнее всего. В чужих полях страницы (`input`, `textarea`,
  `select`, `contenteditable`) не перехватывается, чтобы не мешать печатать.
- Срабатывает только на доверенных событиях (`event.isTrusted`): иначе любой
  скрипт на странице может синтетическим нажатием тратить токены пользователя.
  Исключение — тестовый хук.
- Пока в настройках идёт запись комбинации, хоткеи не срабатывают, а `Esc`
  отменяет запись, не закрывая панель.
- `Esc` и `X` закрывают панель; `Enter` в поле вопроса перестраивает пирамиду.
- `Enter` в поле фокуса запускает перестройку, не отправляя форму на сайте
  (`preventDefault()` на `submit`).
- Пункты меню: «Открыть пирамиду», «Настройки», «Очистить кэш».
- Повторный хоткей при открытой панели закрывает её (и отменяет запрос).
- Один активный запрос: новый вызов сначала `abort()` предыдущего.

## 7. Структура файла

Один файл, секции по порядку:
1. Заголовок `==UserScript==` (дословно из ТЗ плюс два гранта из §6.5):

```javascript
// ==UserScript==
// @name         AI Multi-level Artifact Pyramid Reader
// @namespace    http://tampermonkey.net
// @version      1.0
// @description  Генерация многоуровневой пирамиды тезисов по горячим клавишам
// @match        http://*/*
// @match        https://*/*
// @grant        GM_xmlhttpRequest
// @grant        GM_setValue
// @grant        GM_getValue
// @grant        GM_listValues
// @grant        GM_deleteValue
// @grant        GM_registerMenuCommand
// @connect      *
// @run-at       document-idle
// ==/UserScript==
```

`@connect *` обязателен: `apiBase` задаётся пользователем, включая
`http://localhost:11434/v1` для Ollama. Без него менеджер молча блокирует
запрос.

2. `CONFIG` — дефолты.
3. Инлайн Readability (или собственный экстрактор).
4. Storage (get/set/prune).
5. Extractor.
6. Sanitizer.
7. API-клиент (стриминг, abort, разбор ошибок).
8. Shadow-панель + стили + полоса фокуса.
9. Окно настроек.
10. Сборка system-сообщения (база + дополнение + фокус).
11. Рендер пирамиды.
12. Триггеры и инициализация.

## 9. Приёмка

Проверяется вручную в Chromium с Tampermonkey на наборе разнородных страниц
плюс локальный стенд, который входит в объём работ. Набор — по одному сайту
на каждый тип вёрстки:

- документация с кодом (MDN, docs.python.org, RFC-редактор) — проверить, что
  блоки кода не сплющены;
- технический блог (Хабр, личный блог на Hugo/WordPress);
- новостная статья с плотным текстом (meduza/bbc/arxiv abstract);
- сайт с тяжёлым фреймворком и кучей обвязки вокруг текста;
- страница без статьи (главная поисковика, каталог товаров) — должно
  сработать предупреждение о коротком тексте.

**Стенд (`test/`)** — тоже наш deliverable, репозиторий пустой:
- `fixture.html` — статья-рыба, подключает `pyramid.user.js`, подменяет
  `GM_xmlhttpRequest` на `fetch` к локальному серверу, `GM_setValue`/`GM_getValue`
  — на `localStorage`. Копия `GM_*`-шимма живёт только в стенде.
- `mock-server.mjs` — Node ≥ 18, без зависимостей: отдаёт SSE-поток с заранее
  записанной пирамидой, умеет `?fail=401`, `?fail=429`, `?slow=1`, `?plain=1`
  (нестриминговый JSON) и `?xss=1` (ответ с `<script>` и `onerror`).
  В ответе эхом отдаёт присланный system-промпт через `?echo=1`, чтобы
  проверять подмешивание фокуса без трат токенов.
- `fixtures/` — сохранённые HTML-копии по одному сайту на тип из списка выше,
  чтобы прогонять извлечение офлайн и ловить регрессии при смене экстрактора.
- `README.md` — как запустить стенд и как поставить скрипт в браузер.

Ручные критерии:
1. Хоткей открывает панель; Esc и X закрывают; фокус не «улетает».
2. Извлечение на каждом сайте из набора даёт тело статьи без меню, футера и
   комментариев; проверяется по блоку «показать отправленный текст».
3. Блоки кода в документации приходят в модель с сохранёнными отступами.
4. Пирамида на английской статье — по-английски, на русской — по-русски.
5. Пирамида содержит 3–5 тем второго уровня и вложенные подтезисы.
6. Пустое поле фокуса → дефолтный промпт; введённый фокус виден в блоке
   `debug: system prompt` в конце ответа стенда и меняет дерево тезисов.
7. Фокус «примеры кода на Go» в статье без Go даёт Executive Summary с
   честным «материала по этому предмету нет», а не выдуманные примеры.
8. Кэш разделён по фокусу: пустой и заполненный фокус не отдают друг друга.
9. `<script>`, `onerror`, `img` из ответа модели не исполняются и не рисуются.
10. Ошибка 401 показывает понятный текст и кнопку «Настройки».
11. Повторный вызов по той же статье отдаёт кэш мгновенно.
12. Отмена посреди стриминга оставляет частичную пирамиду в режиме чтения.
13. Тёмная и светлая тема читаемы; панель не ломается при ширине 375 px.
14. Стили сайта не влияют на панель (проверка на сайте с агрессивным CSS).
15. С DeepSeek: пока модель думает, бейдж «модель думает…» с таймером, а не
    пустая панель; в подвале появляются `completion_tokens` из финального
    чанка.

## 10. Риски

- **Разные сайты извлекаются по-разному.** Readability где-то добирает
  комментарии, где-то режет статью. Смягчение: один путь + блок «показать
  отправленный текст» + офлайн-фикстуры в `test/fixtures/`, чтобы видеть
  регрессии, а не догадываться.
- **Стриминг в `GM_xmlhttpRequest` нестабилен у части менеджеров.**
  Смягчение: детект «сервер вернул целый JSON» (§6.3), деградация до
  нестримингового показа без потери функциональности.
- **Очень длинные статьи не влезают в контекст.** Смягчение: `maxChars`,
  обрезка по абзацу, явная пометка в панели, поле в настройках.
- **Модели любят отдавать markdown вместо HTML.** Смягчение: жёсткий промпт
  + постобработка (снять ```html-обёртку, если пришла).
- **Лимиты `GM_setValue`.** Смягчение: 10 записей, 96 КБ на запись, prune.
- **Reasoning-модель долго молчит.** DeepSeek в режиме размышлений может
  минуту не присылать `content`. Смягчение: состояние `thinking` с таймером
  (§6.7) плюс кнопка «Отменить»; пользователь видит, что работа идёт.
- **Имя модели устаревает.** `deepseek-flash` может не знать старый аккаунт.
  Смягчение: поле `model` редактируемое, пресеты — просто заполнение полей.
